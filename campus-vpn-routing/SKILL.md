# 浙大网站 VPN 分流排障

只处理 `zju.edu.cn` 主域名与全部层级子域名。用户给出的某个浙大报错页面是验证样本，不应把任务缩小成只修这个子域名，也不扩展到其他学校。

## 工作流

1. 确认客户端、当前订阅、代理组、规则/全局模式、TUN 与系统代理状态。读取全局脚本、订阅扩展、前置规则和最终运行时规则，仅提取相关字段，避免输出订阅链接、节点凭据、控制密钥、Cookie 或其他网站连接记录。
2. 复现用户的原始 URL。记录错误层次：DNS 解析失败、TCP 超时、TLS 关闭、HTTP 错误、页面资源/API 失败。`ERR_CONNECTION_CLOSED` 本身不能证明是 DNS 或 VPN 的问题。
3. 对同一公开 URL 对照测试真实直连与当前代理。TUN 开启时，`curl --noproxy '*'` 只绕过显式代理，仍可能经过 TUN；如需短暂关闭 TUN，应保存状态、确保自动恢复，并验证实际接口与路由。内核节点延迟测试只能作为线索，仍要验证完整 URL 和浏览器。
4. 按证据选择整个浙大域名的出口：直连正常则使用 `DIRECT`；直连失败而现有代理正常则使用已验证的代理组；两者都失败则继续区分服务器故障、浙大内网、身份认证和当前网络限制，不连续猜测修改。商业代理不等于浙大官方 VPN。
5. 为浙大全域名建立持久规则。`DOMAIN-SUFFIX,zju.edu.cn,<出口>` 同时覆盖主域名和任意层级子域名，不写成 `DOMAIN-SUFFIX,*.zju.edu.cn,...`。把规则放到兜底规则之前；需要所有订阅共用时，优先使用全局扩展脚本合并规则，不修改下载的订阅原文。
6. 清理本任务先前创建的冲突规则和重复的单站点补丁。保留用户既有配置；若已有全局 `main`，合并进原函数，不直接用模板替换。核对后续订阅扩展是否把全局结果覆盖或把冲突规则再次插到前面。
7. 仅在证据表明真实 IP 缓存导致域名丢失时，考虑域名嗅探。`parse-pure-ip` 会识别其他未获得域名的连接，并非只对校园域名生效；解释这个范围，保留已有协议设置与跳过列表，不改变无关 DNS、IPv6 或 TUN 开关作为默认修复。
8. 保存后核对实际运行时配置与实际连接链路，然后刷新用户的原始页面。抽查多个不同子域名、主站及曾有旧 IP 缓存的路径，确认页面正文、图片或必要 API 能加载。报告配置覆盖范围、已测试样本和未验证事项，不能把少量样本通过表述成所有校园服务均可访问。

## 资源选择

- 首次复刻、需要具体界面步骤或命令示例时，阅读 [中文教程与 ZJU 案例](references/replication-guide.md)。
- 需要生成全局扩展脚本时，使用 [浙大专用脚本模板](assets/global-domain-routing.js)，域名固定为 `zju.edu.cn`，只调整出口、订阅到代理组的映射和嗅探开关。它是配置素材，不是自动修改网络的安装脚本。
- 代理组必须在当前订阅中存在且出口已验证。未知订阅的组名不能随意取“第一个 select”，因为它可能默认直连或拒绝；模板会在映射不明确时停止生成配置。

## 非直观的约束

- Clash Verge Rev 的全局覆写 `rules` 数组可能整体替换原有规则；添加规则时通过脚本合并。新版不把全局 Merge 的旧式 `prepend-rules` 当作真正的前置规则。
- “全局扩展脚本”表示适用于所有订阅，不表示要把网络代理模式切换成“全局”。保持用户选定模式，若当前模式使规则不生效，说明原因并做必要调整。
- 全局脚本之后仍可能有订阅扩展和应用设置回写，所以保存成功、文件中出现规则或延迟测试成功都不足以证明浏览器修复。
- 运行服务内核的 socket/配置路径可能不同于用户目录中的生成文件。按进程参数发现实际控制通道，不硬编码上一次机器的临时路径或默认密钥。
- `dig` 和系统/浏览器可能使用不同缓存；fake-IP 是 TUN 映射机制，看到它不等于 DNS 污染。TLS 嗅探依赖可识别的服务器名，无法保证恢复所有无域名 IP 连接。
- 按当前环境要求处理设置修改和文件写入权限；该 skill 不扩大授权。对照测试要恢复原状态，正式修复不得意外关闭 VPN。

## 完成标准

最终规则覆盖 `zju.edu.cn` 和全部子域名；选定出口有对照证据；原始浙大报错页面在浏览器中可访问；相关扩展与更新不会静默覆盖修复。跨订阅策略的映射经过检查，未实际切换测试时应区分“配置覆盖”与“该订阅连通性已验证”。
